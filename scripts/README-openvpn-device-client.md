# Массовое обновление OpenVPN для VPN компьютера

Скрипт: `deploy-openvpn-device-client.ps1`. Он устанавливает MSI, создаёт
`config-auto\device.ovpn` из утверждённого шаблона и назначает доступ к
закрытому ключу. Сертификат он не запрашивает. На ПК уже должны быть
`OpenVPNService` и действующий сертификат компьютера из `AL-ISSUING-CA` с CN
`<имя-ПК>.aurora-logistics.local` и EKU Client Authentication. Применять после
добавления ПК в группу автоэнролмента и получения сертификата.

## Запуск через RMM

Разместить одобренный MSI и **проверенный на пилоте** шаблон `.ovpn.tmpl` в
SYSVOL. Шаблон должен быть в UTF-8. В строке `cryptoapicert` нужен маркер
`{{COMPUTER_FQDN}}`, например `cryptoapicert "SUBJ:{{COMPUTER_FQDN}}"`. Скрипт
подставляет FQDN текущего ПК. Остальные параметры профиля, включая адрес
сервера, проверку его сертификата и при необходимости `tls-crypt`, нужно взять
из рабочего пилотного профиля. Не помещать в шаблон закрытый ключ компьютера
или `auth-user-pass`.

Один раз вычислить SHA-256 обоих файлов командой
`(Get-FileHash -Algorithm SHA256 <путь-к-файлу>).Hash`. Выполнить
скрипт из 64-битного PowerShell 5.1 от `SYSTEM` или локального администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy-openvpn-device-client.ps1 `
  -MsiPath '\\aurora-logistics.local\SYSVOL\aurora-logistics.local\software\OpenVPN-2.7.8-I001-amd64.msi' `
  -TargetVersion '2.7.8' `
  -ExpectedSha256 '<SHA-256 MSI>' `
  -ProfileTemplatePath '\\aurora-logistics.local\SYSVOL\aurora-logistics.local\software\openvpn-device.ovpn.tmpl' `
  -ExpectedProfileSha256 '<SHA-256 шаблона>'
```

Пути, имена и хэши заменить на фактические. Шаблон копируется и читается до установки;
MSI копируется локально, чтобы обновление могло разорвать существующий VPN.
Хэши и подпись MSI проверяются до `msiexec`. Профиль записывается без BOM с
ACL `SYSTEM:Full`, `Administrators:Full`, `OpenVPNService:Read`. Если профиль
меняется, предыдущий сохраняется рядом с расширением `.bak`, которое служба
не загружает. Если установленная версия уже не ниже целевой, MSI из SYSVOL не
нужен, но шаблон всё ещё должен быть доступен для сверки. Код выхода `0` —
успешно, `3010` — MSI попросил перезагрузку, остальные — ошибка.
Перезагрузка не выполняется автоматически.

### Если GPO запрещает PowerShell-сценарии

Проверить на целевом ПК `Get-ExecutionPolicy -List`. Если показано
`MachinePolicy = Restricted`, параметр запуска `-ExecutionPolicy Bypass` из
примера выше не поможет: политика компьютера из GPO имеет приоритет. Режим
`FullLanguage` сам по себе не разрешает запуск файлов `.ps1`. Найти GPO,
задавшую запрет, можно через отчёт `gpresult /h C:\ProgramData\vpn-gpo.html`
и просмотр его в браузере.

Для группы пилотных компьютеров настроить в GPMC политику **Конфигурация
компьютера → Политики → Административные шаблоны → Компоненты Windows → Windows
PowerShell → Включить выполнение сценариев**. Вариант с наименьшей подготовкой:
**Включено → Разрешить локальные сценарии и удалённые подписанные сценарии**
(`RemoteSigned`). Связать GPO с OU целевых компьютеров, ограничить применение
группой `App-VPN-Device-Tunnel` и проверить приоритет относительно существующей
GPO с `Restricted`. Если запрет задан принудительной политикой, менять её
область действия или согласовывать исключение с владельцем политики.

RMM должен сначала положить проверенный `.ps1`, MSI и шаблон локально и затем
запустить сценарий от `SYSTEM`, передав локальные пути. Удалённые компьютеры
без работающего VPN могут не получить новую GPO или файлы из SYSVOL до первого
подключения к доменной сети. После применения GPO проверить
`Get-ExecutionPolicy -List` и запуск на одном пилотном ПК. Если RMM сохранил
на `.ps1` метку Internet Zone (`Zone.Identifier`), `RemoteSigned` потребует
подписи; после проверки хэша и происхождения файла метку можно снять командой
`Unblock-File`.

Если корпоративное требование допускает только подписанный код, выбрать в той
же GPO **Разрешить только подписанные сценарии** (`AllSigned`), подписать
окончательную версию `.ps1` сертификатом Code Signing и распространить доверие
к издателю. Подпись сама по себе не запускает скрипт при `Restricted`.

Для обновления прав после перевыпуска сертификата запускать этот же скрипт
периодически через RMM. При использовании ГПО сначала разместить скрипт и
шаблон локально на клиентах, пока они доступны в домене: запуск прямо из
SYSVOL при старте удалённого ПК до поднятия VPN может не состояться.
Если шаблон содержит общий `tls-crypt` ключ, ограничить чтение исходного
файла в SYSVOL только нужными компьютерными учётными записями.

Скрипт работает с программными машинными ключами Microsoft Software KSP (CNG)
и Microsoft RSA CSP. При TPM/HSM или ином провайдере он завершится с ошибкой,
не изменяя права на посторонние ключи. Ключ не экспортируется; изменяется
только ACL конкретного контейнера. На время перекрытия старого и нового
сертификатов доступ назначается обоим действующим ключам.

Сервер `spb-vpn-srv` использует отдельный машинный пул `10.253.91.0/24`,
`max-clients 250` и не использует CCD. Машинный пул назначен AD Site
`SITE-SPB-DC`. Межсетевые правила пока допускают только DNS на VPN-сервере и
обращения к `SPB-DC1-AL` (`10.78.3.50`) для начальной доменной обработки.
Доступ к CA01 для продления сертификата ещё не настроен. Этот клиентский
скрипт серверную политику не меняет. Перед массовой волной выполните
[проверку загрузки и компьютерных GPO](README-openvpn-device-test.md).

## Проверка и откат

На клиенте проверить `Get-Service OpenVPNService`, версию
`C:\Program Files\OpenVPN\bin\openvpn.exe`, ACL ключа и лог профиля. После
перезагрузки без входа пользователя проверить на `spb-vpn-srv` время нового
соединения и CN компьютера. Изменение ACL можно откатить точечным
`icacls <путь-к-конкретному-ключу> /remove:g 'NT SERVICE\OpenVPNService'`;
профиль — возвратом созданного `.bak` в `device.ovpn`, версию OpenVPN —
установкой ранее утверждённого MSI. Скрипт не меняет УЦ, шаблон сертификата
или сервер OpenVPN.
