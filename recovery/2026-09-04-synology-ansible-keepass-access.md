# Доступ ansible к Synology spb-file

Дата: 2026-09-04.

## Изменение

- Проверен SSH-вход `ansible@10.78.2.210` с паролем стандартной automation
  учётной записи из локального `ansible_al` vault.
- В KeePass добавлена уникальная запись `/Servers/spb-file-synology-ansible`
  с URL DSM, логином `ansible` и подтверждённым паролем.
- Исходная неоднозначная пара записей `/Servers/New Group/nas` не удалялась.
- Перед изменением сделана копия
  `/home/admin-al/work/passwords.kdbx.pre-synology-ansible-20260904-1330`.

## Проверка

Повторный SSH-вход с паролем, прочитанным из новой записи KeePass, успешен.
Узел идентифицируется как `spb-file`, модель RS2421RP+, DSM 7.2.2. Пользователь
входит в группу `administrators`.

## Замечание

Для `ansible` не создан `/var/services/homes/ansible`, поэтому SSH сообщает
об отсутствующем home. На аутентификацию и read-only команды это не влияет,
но перед автоматизацией с загрузкой файлов следует создать/включить home.

## Откат

Удалить только запись `/Servers/spb-file-synology-ansible` либо восстановить
названную резервную копию базы KeePass. Учётная запись DSM этим действием не
создавалась и не изменялась.

Relogin/reboot не требуется.

## Актуализация доступа 2026-10-15

- Подтверждён рабочий SSH-доступ к старой полке `spb-file`
  (`10.78.2.210`) под учётной записью `ansible`.
- Пароль этой учётной записи совпадает с паролем, которым bootstrap-роль
  Ansible назначает пользователю `ansible` на MikroTik. Единственный источник
  секрета: локальный, некоммитируемый файл
  `/home/admin-al/ansible_al/inventories/production/group_vars/mikrotik/vault.yml`,
  переменная `mikrotik_bootstrap_ansible_password`. Секрет в документацию,
  историю shell, журналы и git не переносить.
- Учётная запись входит в DSM-группу `administrators`; для команд root нужен
  `sudo` с тем же паролем. Ключевая аутентификация для неё не настроена.
- У пользователя отсутствует домашний каталог, поэтому предупреждение SSH
  `Could not chdir ...` ожидаемо и на выполнение команд не влияет.

Пример безопасной операционной схемы: извлечь пароль только в память текущего
процесса, передать его в `sshpass` через переменную окружения и в `sudo -S`
через stdin; не использовать пароль как аргумент командной строки.
