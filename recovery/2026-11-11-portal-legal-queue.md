# Подключение юридической очереди HESK к PortalAL

Дата: 2026-11-11. Пользователь разрешил реализовать вторую очередь в портале без почтового ящика; группа AD юридических исполнителей пока не определена, пилотный доступ исполнителей ограничивается администраторами портала. Почтовые шаблоны не менять.

## До изменения

- PortalAL: отдельный Git-репозиторий `~/assistant/apps/internal-employee-portal`, production CD на `10.78.3.149` через GitHub Actions.
- ИТ bridge: `10.78.3.1:9088`, `/opt/hesk-portal-bridge`; HESK `/var/www/helpdesk.aurora-logistics.ru/html`.
- Юридический HESK: `/var/www/hesk-legal/html`, БД `helpdesk_legal` на `10.78.3.2`; почтовый импорт выключен.
- В портале один глобальный URL bridge, старые API `/api/hesk` и `/api/hesk-requests` и журнал идемпотентности без номера очереди.

## План и откат

1. Развернуть отдельный юридический bridge на другом порту с отдельным HMAC-секретом, доступным только `10.78.3.149`, и выключенной отправкой почты. Старый bridge оставить как есть. Сохранить резервную копию nginx перед правкой; откатить новой конфигурации nginx и каталога bridge без влияния на 9088.
2. Обновить PortalAL с `queueId=it|legal`, отдельными API и проверками доступа. Старые маршруты остаются привязанными к ИТ. Откат портала — предыдущий образ/коммит, старый bridge остаётся доступен.
3. Новые колонки `queue_id` в PostgreSQL создаются с `default 'it'`, чтобы старые записи сохранили смысл. При откате кода их можно оставить: это добавочные колонки, не влияющие на прежний код.
4. До записи рабочих заявок подтвердить резервное копирование юридической БД и каталога вложений.

## Выполнено

- На веб-сервере `10.78.3.1` создан `/opt/hesk-legal-portal-bridge` и nginx listener `:9089` (только `10.78.3.149`). Конфигурация с отдельным HMAC-секретом находится в каталоге bridge, `mail_enabled=false`. Для HESK `force_ssl=1` во внутреннем FastCGI указан `HTTPS on`. Старый `:9088` и почтовые шаблоны не изменялись.
- В юридической БД создана пустая совместимая таблица `hesk_plugin_ldap` для существующего `LEFT JOIN` bridge; LDAP-синхронизация не включена. Пилотный исполнитель `a.kuznetsov` создан с отдельным локальным паролем; секреты записаны в `/etc/hesk-legal/credentials.json` (root, 0600).
- В `/opt/portal-al/.env` на `10.78.3.149` добавлены `HESK_LEGAL_BRIDGE_URL` и `HESK_LEGAL_BRIDGE_SHARED_SECRET`, прежняя версия сохранена как `.env.before-legal-20261111` (0600). `PORTAL_LEGAL_GROUP_DN` пока не установлен: доступ исполнителя есть только у администраторов портала, затем требуется сопоставленный профиль HESK.
- PortalAL: коммит `2cd5005` добавляет `queueId=it|legal`, API `/api/service-desk/queues/:queueId`, страницы `/legal/requests` и `/legal/tickets`, отдельный выбор bridge и `queue_id` в идемпотентности. Старые URL закреплены за ИТ.
- Локальные ежедневные резервные копии: на `10.78.3.2` `hesk-legal-db-backup.timer` (04:20 MSK, `/var/backups/hesk-legal`, 14 дней); на `10.78.3.1` `hesk-legal-files-backup.timer` (04:25 MSK, тот же каталог, 14 дней). Начальные копии `helpdesk_legal-20261111-211012.sql.gz` и `files-20261111-211012.tar.gz`; таймеры активны, повторные копии выполнены, gzip и tar прочитаны.
