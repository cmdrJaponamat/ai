# PortalAL: сессии в PostgreSQL

Дата: 18.11.2026. Узел портала `10.78.3.149`, БД на `10.78.3.2`.

Проблема: периодические HTTP 500 на разных страницах. В журнале сервера найден `SyntaxError: Unexpected end of JSON input` при `JSON.parse` в `server/session-store.mjs`: параллельный запрос мог прочитать файловую сессию во время записи. Запрос новостей после предыдущего выпуска отвечал 200/304; ошибка не ограничивалась новостями.

Изменения: PR #10, merge `0fc68dda65ad0da6e8e3d08dbfde09521a24824a`, образ `portal-al:0fc68dda65ad0da6e8e3d08dbfde09521a24824a`. Добавлен `PostgresSessionStore`, идемпотентная подготовка `portal_sessions` до переключения образа и часовая очистка истёкших строк. После выпуска образа при старом режиме в `/opt/portal-al/.env` изменена только строка `PORTAL_SESSION_STORE=file` на `postgres`; копия прежнего файла `/opt/portal-al/.env.before-pg-sessions-20261118` (0600). Контейнер пересоздан тем же образом. Старые файловые сессии сохранены, но не импортированы; пользователи проходят SSO повторно.

Проверка: 79 тестов и сборка; изолированный staging с PostgreSQL-сессиями прошёл для обеих очередей, в тестовой БД появилась запись сессии. PR CI, CI `main`, staging и production workflow успешны. В production таблица доступна runtime-роли с DML-правами; `set/get/touch/destroy` прошли через рабочий контейнер; образ healthy, `/api/health` 200, 13 активных сессий в БД на момент проверки, `/api/news?includeDrafts=1` ответил 304, новых `SyntaxError` и HTTP 500 в свежих логах не было.

Откат: вернуть `PORTAL_SESSION_STORE=file` из указанной копии `.env` и пересоздать контейнер с текущим образом. Для отката на образ до PR #10 возврат `file` обязателен, иначе старый образ не запустится. Таблица `portal_sessions` может остаться. Перезапуск контейнера выполнен; перезагрузка ОС не нужна.
