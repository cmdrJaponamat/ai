# SPB-NAS1: возврат default route на сервисный eth7

Дата: 2026-11-24, MSK. Изменение согласовано владельцем. Исходная схема и целевые префиксы: `2026-11-23-veeam-exchange-nfs-route-diagnostic.md`.

## Перед изменением

- Veeam `bkp_exchange_dag02`: сессия 23.11 18:00:23 — 24.11 01:09:27, `Success/Stopped`, длительность 7 ч 09 мин; предыдущая субботняя сессия 21.11 18:00 — 23.11 10:09, также `Success/Stopped`.
- NAS `SPB-NAS1`: `eth1=10.78.0.250/24`, `eth4=10.78.5.10/24`, `eth7=10.78.7.10/24`; default `via 10.78.0.254 dev eth1`; статических маршрутов DSM нет. По `ip route get`, ответы к Veeam `10.78.20.99` идут через eth1. DSM API `SYNO.Core.Network.Router.Static.Route/get` вернул `rules=[]`.
- Текущий Admin VPN-клиент `10.78.90.35/27` подключается к management-адресу NAS; Zabbix `10.78.3.251` опрашивает `10.78.0.250`. Оба шлюза `10.78.0.254` и `10.78.7.254` отвечают с соответствующих интерфейсов NAS. На NAS есть активные NFS/SMB/iSCSI-сессии.

## План изменения и отката

1. Через DSM API создать постоянные маршруты `10.78.90.32/27 via 10.78.0.254 dev eth1` и `10.78.3.251/32 via 10.78.0.254 dev eth1`; проверить `ip route get` и SSH/HTTPS из VPN.
2. Перед изменением default запустить на NAS независимый таймер автоматического отката к `10.78.0.254 dev eth1`; сохранить его PID и отменить только после проверок. Изменить default на `10.78.7.254 dev eth7` штатным DSM-средством.
3. Проверить пути к `10.78.20.99`/`.100`, Admin VPN, Zabbix, доступ SSH/DSM, NFS/iSCSI и конфигурацию DSM. Убедиться, что настройка переживёт обновление сети или перезапуск; без этого считать изменение временным.
4. Ручной откат при недоступности: через локальную консоль NAS или оставшийся SSH вернуть `synonet --set_gateway 10.78.0.254`. Если нужно удалить новые маршруты, использовать DSM API Static Route `set` с пустым списком `rules`, только после сверки текущего списка.

## Выполнено

1. В DSM API `SYNO.Core.Network.Router.Static.Route` созданы и включены две постоянные записи: `10.78.90.32/27 via 10.78.0.254 dev eth1` и `10.78.3.251/32 via 10.78.0.254 dev eth1`. Метод `test` обе записи принял; `get` возвращает обе со статусом `Enabled`.
2. До смены default на NAS был запущен независимый 420-секундный таймер возврата шлюза `10.78.0.254` (PID 2652). После добавления статических маршрутов проверены SSH и HTTPS DSM через действующий VPN `10.78.90.35`.
3. Штатной командой `synonet --set_gateway 10.78.7.254` переключён default на `eth7`. Через DSM API `SYNO.Core.Network.Ethernet/set` для уже статического `eth7` установлен `gateway=10.78.7.254` и `is_default_gateway=true`, остальные параметры интерфейса сохранены. Это закрепило шлюз в конфигурации интерфейса и сервисном порядке DSM: `eth7` priority 0, `eth1` priority 1; `eth4` без шлюза.
4. После проверок таймер отката остановлен (PID 2652, дочерний sleep PID 2653); его команда не выполнялась. Маршрут к Veeam остаётся через `eth7`.

## Проверка после изменения

- `ip route get 10.78.20.99` и `.100`: `via 10.78.7.254 dev eth7 src 10.78.7.10`.
- `ip route get 10.78.90.35` и `10.78.3.251`: `via 10.78.0.254 dev eth1 table static-table src 10.78.0.250`.
- `ip route get 10.78.5.11`: напрямую через `eth4 src 10.78.5.10`; локальная сервисная сеть `10.78.7.0/24` — через `eth7`.
- SSH и HTTPS DSM на `10.78.0.250` из действующего VPN сохранились; HTTPS на `10.78.7.10` также отвечает. Zabbix API показал свежие SNMP-показатели NAS на 24.11 12:06 MSK после переключения.
- На NAS сохранены установленные TCP-соединения NFS `10.78.7.10:2049` ↔ worker `10.78.20.100` и iSCSI `10.78.5.10:3260` ↔ `10.78.5.11/.12`. ICMP к `.99/.100` не ответил; по одному ICMP доступность NFS не оценивается. Гостевой агент worker VM133 сообщил `guest-exec has been disabled: the agent is in frozen state`, поэтому отдельный тест из гостя не выполнен.
- DSM API `SYNO.Core.Network/get` показывает default `10.78.7.254` на `eth7`; `Gateway.List/get` — `eth7` первым, `eth1` вторым; Static Route `get` — обе записи `Enabled`. Перезагрузка и перезапуск сети не выполнялись. Сохранение после будущей перезагрузки подтверждено конфигурацией DSM, но фактическим reboot не проверено.

## Откат и следующий контроль

Для отката default: `sudo /usr/syno/sbin/synonet --set_gateway 10.78.0.254`; затем в DSM для `eth7` убрать `gateway` и флаг default, либо выставить `eth1` первым в Service Order. После этого убедиться в `ip route get 10.78.20.99`. Две статические записи могут остаться: они сохраняют доступ к management; при необходимости удалить их через DSM Static Route после сверки списка. Рестарт служб и перезагрузка не требуются.

Следующий контроль: проверить сессию `bkp_exchange_dag02` после планового запуска 24.11 в 18:00 и фактический исходящий поток NAS по `eth7` во время backup. Утренний `Success` относится к backup **до** изменения маршрутов.
