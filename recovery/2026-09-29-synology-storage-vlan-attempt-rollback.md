# SPB-NAS1: попытка добавить второй VLAN на текущий bond — откат

**Дата:** 2026-09-29  
**NAS:** `SPB-NAS1` / `spb-file-cloud`, management `10.78.0.250`

## Цель

Добавить storage VLAN к файловому VLAN1070 на текущем DSM `bond0` из двух 10GbE
портов, не затрагивая MSA/PVE iSCSI.

## Установленные факты

- DSM `bond0` — active/standby (`eth4` active, `eth7` standby), текущий
  файловый адрес `10.78.7.10/24`;
- активный `eth4` физически приходит на H3C-2 / lower
  `XGE1/0/54:2`, несмотря на устаревшую подпись этого порта `standby`;
- следовательно, единственная допустимая storage-fabric для текущего active
  пути — VLAN1050 / `10.78.5.0/24`, а не VLAN1040;
- штатная DSM-команда `synonet --vlan_create bond0 <id> <ip> <mask>` превращает
  адресованный `bond0` в VLAN-интерфейс и снимает L3-конфигурацию с parent
  `bond0`. `synonet --manual bond0 ...` при существующем VLAN возвращает
  `Invalid network interface [bond0]`.

Иными словами, на данной версии DSM нельзя штатно держать одновременно
`bond0=10.78.7.10/24` и `bond0.<storage-vlan>` как второй L3-интерфейс.

## Что было временно изменено и возвращено

1. На верхнем H3C `XGE1/0/54:2` кратко добавлялся tagged VLAN1040; затем порт
   возвращён в исходный access VLAN1070.
2. В DSM временно создавался `bond0.1040=10.78.4.10/24`, затем удалён.
3. После установления фактической физической привязки на нижнем H3C
   `XGE1/0/54:2` кратко добавлялся tagged VLAN1050; затем порт возвращён в
   исходный access VLAN1070.
4. В DSM временно создавался `bond0.1050=10.78.5.10/24`, затем удалён.
5. `bond0` вручную возвращён к `10.78.7.10/24` штатной командой DSM.

## Финальная проверка

- `synonet --vlan_enum`: `No VLAN Exist`;
- `bond0` UP с `10.78.7.10/24`, active slave `eth4`, оба 10GbE slave UP,
  Link Failure Count 0;
- PVE1/PVE2 после ARP refresh проходят до `10.78.7.10` 5/5;
- все 8 путей MSA multipath остаются `active/running/ready`.

## Безопасная следующая схема

Для реального storage-подключения NAS нужен **отдельный физический сетевой
интерфейс** (предпочтительно 10GbE), не входящий в файловый `bond0`:

- оставить `bond0` и оба текущих линка исключительно для VLAN1070 /
  `10.78.7.10`;
- отдельный NAS NIC подключить только к H3C-2 / lower в access VLAN1050 и
  назначить ему `10.78.5.10/24` без gateway;
- либо сначала обеспечить дополнительную 10GbE карту/порт. Не объединять этот
  NIC с `bond0` и не переносить NAS на обе fabric: это не даст multipath.

## Откат

Состояние уже возвращено к исходному: оба NAS-порта H3C access VLAN1070,
DSM VLAN-интерфейсов нет. При появлении отдельного NIC использовать только
новый порт; существующий `bond0` не менять.
