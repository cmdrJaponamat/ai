# Замена DC2 в Мурманске: подготовка MMK-DC1-AL

Дата: 2026-11-05. Площадка: Мурманск, Тарана 25. Система: `aurora-logistics.local`.

## Задача и подтверждённый контекст

- Пользователь готовит Windows Server 2019 в СПб на `192.168.203.40` для перевозки на Тарана. Постоянное имя: `MMK-DC1-AL`. После вывода старого DC2 желаемый адрес: `10.10.20.50`. На переходное время выбран `10.10.20.51`.
- По решению пользователя DC и сервер печати будут размещены в одной Windows Server 2019. Microsoft рекомендует выключать Print Spooler на DC; совместное размещение принимается как эксплуатационный риск и требует ограничений доступа и драйверов.
- `SITE-MMK` уже существует. `DC2` (`10.10.20.50`, Windows Server 2019 Standard) находится в нём, является writable GC. `SPB-DC1-AL` (`10.78.3.50`) находится в `SITE-SPB-DC`. Все пять FSMO-ролей находятся на SPB-DC1-AL.
- `10.10.0.0/16`, `10.11.0.0/16`, `10.12.0.0/16`, `10.13.0.0/16`, `10.17.0.0/16` и `192.168.103.0/24` привязаны к `SITE-MMK`. Сеть текущего расположения `192.168.203.0/24` привязана к `SITE-SPB-MILLION`.
- `SL-AD-TRANSITION` соединяет `SITE-MMK` и `SITE-SPB-DC` с интервалом 15 минут. Домен и лес имеют уровень Windows Server 2016, миграция SYSVOL на DFSR завершена. `repadmin /replsummary` с SPB-DC1-AL: 0 ошибок в доступном направлении; известный удалённый опрос DC2 возвращает 110 из этой SSH-сессии.
- Локальная адресация Тарана: серверный VLAN 20 `10.10.20.0/24`, шлюз `10.10.20.1`. Целевая сегментация предусматривает отдельные сети для принтеров и print-node, но на Тарана они ещё не подтверждены как введённые.
- Имя `MMK-DC1-AL` отсутствовало в AD и DNS на момент проверки. DHCP сети `10.10.30.0/24` на `AL-MMK` прямо выдаёт DNS `10.10.20.50`; это подтверждает необходимость контролируемого возврата адреса `.50` новому DC. Сам шлюз использует DNS `10.78.4.253`.
- В `OU=Domain Controllers` прямо связана `Default Domain Controllers Policy`; отчёты действующих GPO не содержат настройки `Spooler`. Это не отменяет риска размещения Print Spooler на DC.

## Резерв временного IP: выполненное изменение на AL-MMK

- Перед изменением на `AL-MMK` (`10.10.30.1`) прочитан DHCP-пул `vlan20DHCP`: `10.10.20.3-10.10.20.60`. Сервер DHCP работает на `vlan20(SERVERS)`. Для `.51` нет lease и PTR; с DC1 ping не отвечает, на шлюзе ARP `status=failed`. Это не абсолютное доказательство отсутствия выключенного статического узла.
- Перед правкой на шлюзе сохранён `/ip pool export` в `mmk-dc1-pool-before-20261105.rsc` (2026-11-05 17:27:48 MSK). Пул `vlan20DHCP` изменён на `10.10.20.3-10.10.20.50,10.10.20.52-10.10.20.60`, исключив `.51`. Повторное чтение подтверждает новое значение, DHCP-сервер `vlan20DHCP` включён, lease `.51` отсутствует. До назначения IP новому серверу повторно проверить ARP, leases и локальную инвентаризацию.
- Откат: только после снятия `.51` с нового сервера либо выбора иного временного IP выполнить на `AL-MMK` `/ip pool set [find where name="vlan20DHCP"] ranges=10.10.20.3-10.10.20.60`. Прочие DHCP-пулы и маршрутизацию не менять.

## Граница подготовки

- Пока новый сервер находится в СПб, оставить текущий IP `192.168.203.40`; можно переименовать, обновить ОС, проверить оборудование, подключить к домену как member server и подготовить средства резервного копирования.
- Уточнение 2026-11-06: первоначальный запрет на повышение в СПб был чрезмерно строгим. Повышать до DC можно сейчас на `192.168.203.40`, выбрав текущий сайт `SITE-SPB-MILLION` и источник репликации `SPB-DC1-AL`. После перевозки назначить `.51`, перенести объект DC в `SITE-MMK`, обновить DNS и проверить репликацию. До переезда этот DC может обслуживать клиентов `SITE-SPB-MILLION`; нельзя публиковать его как DC `SITE-MMK` на адресе СПб. Подробности в runbook.
- Уточнение развёртывания без выезда администратора: после полной проверки DC и RMM в СПб статический `.51` можно задать последним действием перед штатным выключением. В офисе местный сотрудник только подключает сервер к проверенному порту VLAN 20 и включает его; перенос объекта в `SITE-MMK`, проверки и смена адреса на `.50` выполняются удалённо. Сеть `10.10.20.0/24` в СПб для этого разворачивать не требуется.
- `DC2` сейчас не выключать ради подготовки: `.50` выдаётся как DNS клиентам VLAN 30, а новый DC на этом адресе одновременно со старым работать не может. Преждевременный вывод `.50` создаёт окно недоступности DNS и локального DC на время перевозки.
- Адрес `.50` назначать новому DC только после штатной демоции DC2, отключения его интерфейса и проверки отсутствия конфликта IP.
- Пошаговые команды для консоли нового сервера и контролируемой замены: [`../scripts/README-mmk-dc1-al-replacement.md`](../scripts/README-mmk-dc1-al-replacement.md).

## Проверка, откат и перезапуски

- Проверка DHCP-резерва: перечитать пул на AL-MMK, убедиться, что `.51` отсутствует в диапазоне выдачи, остальные диапазоны сохранены.
- Для изменения пула перезагрузка маршрутизатора, сервера и клиентов не требуется. Для переименования, вступления в домен, промоции и демоции DC перезагрузка потребуется на соответствующих Windows Server.
- Подготовка нового сервера и вывод DC2 ещё не выполнялись; доступа к новому серверу сейчас нет.
