# Закрытие заявки в PortalAL без лишнего подтверждения

Дата: 2026-11-12. В рабочем месте исполнителя ИТ и юридической очередей кнопка «Закрыть заявку» всегда показывала браузерное подтверждение «Закрыть заявку без сообщения заявителю?», независимо от истории ответов и черновика.

## Изменение

- В `~/assistant/apps/internal-employee-portal/src/features/service-desk/HeskTicketDrawer.tsx` убрано безусловное `window.confirm`.
- Если написан ответ заявителю, кнопка показывает «Отправить ответ и закрыть» и вызывает ответ исполнителя со статусом `3` вместе с вложениями; отдельный запрос закрытия не требуется. При пустом поле ответов заявка закрывается обычным запросом.
- Несохранённая внутренняя заметка и вложения без текста блокируют закрытие с сообщением внутри карточки, чтобы черновик не потерялся.
- Коммит PortalAL: `8ee923f`; предыдущий рабочий образ: `portal-al:2cd5005474314eee4eafa870b356c1ac198005d7`.

## Проверка и откат

- Локально: `git diff --check` и `npm run build` прошли. CI прошёл. Новый контейнер `portal-al:8ee923ff57698cca2a457db7c7b3511fd55bef9a` healthy, `/api/health` и `/legal/tickets` возвращают HTTP 200. В собранном JS есть новый текст кнопки и отсутствует старый текст подтверждения. Нажатие в авторизованном браузере ещё не проверено.
- Откат: `git revert 8ee923f` в PortalAL и дождаться штатного CD либо вернуть предыдущий образ через штатный deploy script. Изменений в БД, HESK, bridge и почтовых шаблонах нет.
- Relogin/reboot не требуется; после CD браузеру может понадобиться обновить страницу, чтобы загрузить новый JS.

## Доработка управления ответом

По просьбе владельца отдельная кнопка закрытия перенесена в блок отправки ответа. Коммит PortalAL `e36f3de` добавляет выбор действия у одной кнопки: «Отправить ответ», «Отправить и закрыть», «Закрыть без ответа». Сохранение внутренней заметки по-прежнему отдельный режим этой формы. Для обычного ответа сохранён выбор статуса, но «Решена» вынесена в явное действие закрытия. Черновик не удаляется при выборе «Закрыть без ответа»: форма показывает ошибку и требует его отправить или очистить.

Локальная сборка и проверка `git diff --check` прошли. Дополнительный коммит `c6e0a42` сбрасывает выбор действия и черновик при переходе к другой заявке, чтобы прежнее действие не применилось к новому тикету. CI и CD обоих коммитов завершились успешно. Работающий контейнер `portal-al:c6e0a42f39b29cf97944679b5745a3a5e6bf5708` healthy, `/api/health`, `/tickets` и `/legal/tickets` вернули HTTP 200; в собранном JS присутствуют новые варианты действий. Авторизованное нажатие в браузере ещё не проверено. Откат этой доработки — вернуть образ `portal-al:8ee923ff57698cca2a457db7c7b3511fd55bef9a` либо откатить коммиты `c6e0a42`, `e36f3de` и выполнить штатный CD.
