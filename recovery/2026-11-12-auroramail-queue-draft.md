# Черновик очереди `info` и ввод IMAP в PortalAL

Дата: 2026-11-12. Пользователь возобновил проект делопроизводителей и подтвердил: доступ к ящику `info` подготовлен, параметры он введёт сам через настройки портала; для операторов будет отдельная группа AD.

## Изменения

- В `assistent` обновлены ТЗ и проектная схема, коммиты `e6741c0`, `924ec3f`, `530c25c`. `info` — отдельный экземпляр общей очереди с подключаемым модулем корреспонденции; backend карточек пока не выбран.
- PortalAL `b735f20`: административный реестр очередей, начальные записи `it`, `legal` (active) и `info` (draft), создание черновиков, страница ввода IMAP для черновика. Новые таблицы `portal_service_queues` и `portal_queue_imap_sources` создаются при первом обращении к реестру. Пароль IMAP шифруется AES-256-GCM, API возвращает только `passwordConfigured`; `enabled=false` принудительно.
- На `10.78.3.149` в `/opt/portal-al/.env` создан `PORTAL_QUEUE_SECRET_KEY`, исходный файл сохранён как `/opt/portal-al/.env.before-info-queue-20261112`. Значение ключа не записывалось в лог и не передавалось в чат. Для расшифровки будущих сохранённых паролей ключ нужно сохранять в резервных копиях.
- AD-группа `App-Portal-Info-Operators` пока только предложена по шаблону; фактическая группа и DN не созданы и не подключены. Почтовый опрос и worker не запущены.
- Исправление навигации PortalAL `3e0d01c`: `info` теперь доступна в селекторе очереди администратору, вкладка «Почта» открывает IMAP-форму напрямую; URL `/admin/queues?queue=info&tab=mail`. Ранее форма была спрятана внутри вкладки «Очереди» за дополнительной кнопкой, из-за чего владелец не смог её найти.
- После ввода владельцем IMAP-параметров проверка из контейнера показала: `mail.aurora-logistics.ru` резолвится во внешний `85.114.6.214`, TCP/993 оттуда недоступен; внутренний `10.78.3.62:993` доступен. TLS с SNI `mail.aurora-logistics.ru` прошёл, вход и `EXAMINE INBOX` в режиме только чтения прошли; UIDVALIDITY=14, UIDNEXT=128595, EXISTS=25646 на момент проверки. Эти числа не записаны в рабочий курсор, опрос остаётся выключенным.
- По предложению владельца вместо отдельного поля адреса подключения добавлена адресная запись `extra_hosts` для контейнера портала в PortalAL `46c2e8a`: `mail.aurora-logistics.ru:10.78.3.62`. Неприменённые правки поля подключения в коде отменены. Production Compose сохранён как `/opt/portal-al/compose.yml.before-mail-host-20261112`; синтаксис нового Compose проверен на production Docker Compose.

## Проверка

- Локально: `npm run build`, 3 профильных теста (реестр, ACL, шифрование), синтаксис Node и проверка diff прошли.
- CI и CD `b735f20` успешны. Production `portal-al:b735f20...` healthy, `/api/health` HTTP 200. Прямое чтение реестра из контейнера вернуло `it=active/hesk`, `legal=active/hesk`, `info=draft/unbound`. Настройки `info` пустые, `enabled=false`, пароль ещё не сохранён. Наличие 64-символьного ключа в контейнере проверено без вывода его значения.
- Исправление `3e0d01c`: локальная сборка, CI и CD успешны; production `portal-al:3e0d01c...` healthy, API health 200, маршрут `/admin/queues?queue=info&tab=mail` внутри контейнера отдаёт HTTP 200, в опубликованном JS есть вариант «Делопроизводство (черновик)». Внешний HTTPS-запрос с этого ПК оборвался на сетевом соединении, поэтому интерактивный вход пользователя не проверен.
- `46c2e8a`: CI/CD успешны, production `portal-al:46c2e8a...` healthy, `ExtraHosts` содержит только почтовую запись. В контейнере `mail.aurora-logistics.ru` резолвится в `10.78.3.62`; TLS по имени проверен. Повторная проверка по обычному имени прошла: вход в IMAP успешен, `EXAMINE INBOX` только для чтения, UIDVALIDITY=14, UIDNEXT=128595, `enabled=false`. В рабочую очередь письма не импортировались.
- Дополнительно после вопроса владельца проверены действующие доски через штатный `getServiceDesk()` из production-контейнера: для `it` и `legal` bridge `available=true`, оператор `a.kuznetsov` найден, список возвращает по одной заявке при `limit=1`. Профильные ACL и навигационные тесты прошли. Первый диагностический вызов использовал ошибочное имя экспортируемой функции; повторная проверка через штатный API успешна.

## Откат

- Портал: `git revert b735f20` в PortalAL и штатный CD либо откат образа по штатной процедуре. Действующие маршруты ИТ и юристов этот коммит не меняет.
- Ключ: после отката кода и до появления сохранённых IMAP-паролей можно восстановить `/opt/portal-al/.env.before-info-queue-20261112`; после сохранения пароля ключ нельзя удалять без повторного ввода пароля.
- Таблицы реестра можно оставить: они не влияют на HESK. При необходимости удалять их только после проверки, что в `portal_queue_imap_sources` нет нужных настроек.
- Для отката адресного переопределения: `git revert 46c2e8a` и штатный CD либо восстановить `/opt/portal-al/compose.yml.before-mail-host-20261112` и пересоздать только `portal` с текущим образом. Запись действует только в контейнере портала; при смене внутреннего IP Exchange обновить её в `compose.yml`.
- Перезагрузка ОС не нужна. Портал пересоздаётся штатным CD; браузеру достаточно обновления страницы.
