# PortalAL: пересылка HTML и отметка прочтения info

Дата: 2026-11-26. Изменение: PR #15, ветка `fix/info-forward-html-read-flag`.

## Проблема

Письмо с пустой `text/plain` и заполненной HTML-частью пересылалось с одними заголовками. Оформление и встроенные CID-изображения при пересылке терялись. Оператор также запросил управление отметкой «прочитано» во «Входящих».

## Изменение

- Пересылка берёт HTML при пустой текстовой части; формирует обычный текст и HTML, сохраняет встроенные CID-изображения.
- Миграция Service Desk `009_imap_read_flag.sql` добавляет `portal_queue_imap_sources.mark_read boolean not null default false` без удаления данных.
- Настройка info находится в «Управление → Настройки очередей → info → Почта». При включении входящее письмо отмечается прочитанным **после** сохранения карточки. В обычном режиме INBOX открыт read-only, чтение выполняется через `BODY.PEEK[]`; просмотр и пересылка не меняют флаг входящего письма.

## Проверка перед выпуском

- Python: 9 тестов обработчика почты, включая пустой plain + HTML + CID и ограничение команды `STORE` настройкой.
- PortalAL: 83/83 теста; `npm run build`; CI PR #15 зелёный.
- Реальное письмо повторно не пересылалось; содержимое ящика не менялось.

## Выпуск и откат

Push в `main` запускает production workflow. Скрипт применяет миграцию до смены контейнера и выполняет health-check; при отказе health возвращает прежний образ. После выпуска проверить workflow, HTTP `/api/health`, `mark_read=false` в БД и отсутствие ошибок в логах IMAP.

**Факт выпуска, 10:46 MSK:** PR #15 объединён в `main` как `122c436f20ceed658f4769032a199abf8fb9fc58`. CI, staging integration и production workflow завершились успешно. На `10.78.3.149` контейнер `portal-al` работает на образе с этим SHA; локальный `/api/health` вернул `{"ok":true,"authMode":"spnego"}`. В БД `portal_al` версия Service Desk равна 9, для `info` `mark_read=false`. Реальную пересылку письма не запускали, чтобы не отправить повторное сообщение адресатам.

Ручной откат: на сервере портала `/opt/portal-al` выставить `PORTAL_IMAGE` прежнего тега из `docker inspect portal-al --format '{{.Config.Image}}'` и выполнить `docker compose up -d --no-build portal`; проверить `/api/health`. Миграцию 009 при откате образа **не удалять**: новый столбец совместим со старым кодом. Если опция была включена, выключить её на странице настроек до отката.

Перезагрузка ОС не нужна; контейнер перезапускается при выпуске.
