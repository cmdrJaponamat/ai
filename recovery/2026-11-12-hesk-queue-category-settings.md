# Управление категориями очередей HESK

Дата: 2026-11-12. Область: PortalAL и два внешних HESK bridge на 10.78.3.1.

## Задача

Вынести категории ИТ и юридической очередей в портал. Юридические исполнители должны управлять только своей очередью, ИТ — только своей, администраторы портала — обеими.

## Изменения

- Страница `/admin/queues/categories` выбирает доступную очередь и показывает категории соответствующей БД HESK. Доступны создание, изменение названия, публичности, важности и штатного срока; удаление только пустой категории с ID не 1.
- API `/api/service-desk/queues/:queueId/settings/categories` проверяет роль на каждом запросе до вызова подписанного bridge. Право определяется по `queueId` из URL, а не по полю браузера.
- Публичный список для формы заявителя отфильтровывает закрытые категории; bridge запрещает создание заявки заявителем в закрытой категории даже при прямом запросе.
- При создании новой категории HESK не назначает её автоматически всем исполнителям. Права операторов на новую категорию нужно проверить отдельно в HESK.
- Существующие категории и заявки не меняются развёртыванием. Для изменения PHP bridge сохранить старые `index.php` обоих экземпляров перед заменой.

## Проверка

Локально: 6 тестов в `queue-category-access`, `service-desk-queues` и `service-desk-reports`, `npm run build`, `git diff --check`, PHP lint обоих bridge — пройдены. Тест проверяет прямые GET/POST/delete юридической роли к ИТ, старый API `/api/hesk`, почту и SLA, а также её доступ к Legal и административный доступ к ИТ.

Production: оба bridge вернули разные списки категорий из своих БД. Создание/изменение/удаление временной категории Legal прошло; значения типа, важности, автоназначения и срока прочитаны обратно. После проверки в Legal снова только `General` с пятью заявками, в ИТ прежние две категории. При диагностике две временные записи `Проверка тест` остались после попытки rollback транзакции на таблице HESK; обе удалены через bridge, конечный список проверен. Исправлены строковые ENUM значения HESK (`autoassign`, `type`, `priority`) и сравнение публичного типа категории в запросе. Проверка read-only SQL подтвердила, что публичная категория №1 обеих очередей доступна. Ни одна реальная категория не изменена.

Итоговый deploy PortalAL `43214433398` успешен; production контейнер использует `1b08acd` и healthy. Страница `/admin/queues/categories` отвечает HTTP 200, неавторизованный API HTTP 401; подписанный bridge возвращает только исходные категории обеих БД. Интерактивный вход под реальным сотрудником юридического отдела не выполнялся; роль проверена интеграционным тестом маршрутов с прямыми запросами.

## Откат

PortalAL: revert коммитов `1b08acd`, `da78408`, `ebddd7b`, `c671929` и дождаться production deploy. HESK bridge: восстановить сохранённые `index.php.before-queue-categories-20261112` в `/opt/hesk-portal-bridge/` и `/opt/hesk-legal-portal-bridge/`. Категории находятся в отдельных БД HESK; при последующих изменениях оператором откат значений выполняется вручную из резервной копии или в HESK. Перелогин и перезагрузка ОС не требуются; для нового интерфейса нужно обновить страницу браузера.
