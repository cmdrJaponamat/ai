# Завершение старых сессий admin-al после повторных блокировок

Дата: 2026-11-16. Статус: четыре сессии завершены, наблюдение за блокировками продолжается.

## Основание

Пользователь запросил завершить старые сессии `admin-al` на узлах, которые доменный контроллер указал как источники блокировок. На `spb-dc1-al` события Security 4740 от 16.11.2026 указали `1C`, `SPB-MX4`, `SPB-WTS-AL`, `SPB-OLIMPOKS`. Пароль `admin-al` установлен 13.11.2026 17:17:33 по обоим DC; все указанные сессии созданы до этой даты. На 10:20 учётная запись не заблокирована, `BadPwdCount=3`, последняя ошибочная попытка 10:14:30. Отдельная проверка служб, заданий с сохранённым паролем и IIS app pools на четырёх узлах совпадений с `admin-al` не обнаружила; причина на уровне конкретного процесса не доказана.

## Целевые сессии и изменение

| Узел / PVE VMID | Сессия | Состояние до изменения |
| --- | ---: | --- |
| `1C`, VM121, `spb-pve2` | 2 | Disc, вход 29.08.2026 |
| `SPB-MX4`, VM135, `spb-pve1` | 2 | Disc, вход 15.10.2026 |
| `SPB-WTS-AL`, VM137, `spb-pve1` | 1 | console Active, вход 25.01.2026 |
| `SPB-OLIMPOKS`, VM139, `spb-pve1` | 3 | Disc, вход 08.10.2026 |

Через QEMU Guest Agent повторно сверить `quser`, затем выполнить `logoff.exe` только для этих ID и проверить отсутствие `admin-al` в списке сессий. Другие сессии не завершать. На `SPB-WTS-AL` завершение активной console-сессии может закрыть её пользовательские процессы; это входит в запрошенное действие.

Откат завершённой сессии невозможен: при необходимости войти заново с актуальным паролем и восстановить закрытые административные программы вручную. Серверы и службы перезагружать не требуется. После завершения проверить состояние учётной записи и новые события Security 4740; отсутствие новых блокировок сразу после изменения не доказывает устранение причины.

## Результат

Через QEMU Guest Agent после сверки `quser` завершены: `1C` ID 2, `SPB-MX4` ID 2, `SPB-WTS-AL` ID 1, `SPB-OLIMPOKS` ID 3. Повторный `quser` подтвердил отсутствие `admin-al` на всех четырёх узлах; чужие сессии остались. На `SPB-MX4` проверочный PowerShell-процесс вернул код 1, потому что после завершения последней пользовательской сессии `quser` сообщил `No User exists`; отдельный повторный опрос подтвердил пустой список сессий.

В 10:22:52 `Get-ADUser` на PDC показал `LockedOut=False`, `BadPwdCount=3`, `LastBadPasswordAttempt=10:14:30` — до завершения сессий. За следующий ожидаемый интервал ошибок требуется повторно посмотреть события 4740 и `LastBadPasswordAttempt`; при возобновлении блокировок источник остаётся открытым для дополнительной диагностики.
