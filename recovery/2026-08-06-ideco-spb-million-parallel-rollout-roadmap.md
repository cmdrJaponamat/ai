# Roadmap: параллельный rollout Ideco на Миллионной

Дата начала: 2026-08-06, MSK
Площадка: Санкт-Петербург, Миллионная 6 (`AL-SPB-MILLION`)
Принцип: новые сети строятся параллельно legacy-сети. Ни один существующий
SSID, VLAN, шлюз или маршрут не изменяется в рамках подготовки.

## Цель

Подготовить Ideco как L3-шлюз целевой site-модели Миллионной, подключённый к
агрегирующему `SPB-SW-409`. Миграция пользователей осуществляется выбором
нового SSID/переводом конкретного switch-порта в новый VLAN. Быстрый откат —
вернуть конкретный порт или пользователя в legacy VLAN либо выключить только
новый SSID; AL-SPB-MILLION продолжает обслуживать существующие сети.

## Целевая физическая схема

```text
                 legacy VLAN / SSID ───────────────→ AL-SPB-MILLION
all UniFi AP ─┬─ SPB-SW-409 ──────────┬─ Ideco LAN trunk: target VLANs
              └─ SPB-SW-410 ──────────┘
SPB-SW-409 ───────────────────────────── Ideco transit: isolated VLAN 1461
SPB-SW-409 ───────────────────────────── Ideco management: legacy management VLAN only
```

`SPB-SW-409` выбран как точка подключения: на нём семь активных AP; ещё
четыре находятся на `SPB-SW-410`. Для покрытия всех точек новые клиентские
VLAN должны быть tagged на AP-портах обоих коммутаторов и на их межкоммутаторном
uplink. Управляющий native VLAN AP не меняется в первой волне.

## Этапы и стоп-условия

| Шаг | Содержание | Статус | Откат |
| ---: | --- | --- | --- |
| 0 | Зафиксировать octet, roadmap, физическую и адресную модель | Выполнен | Вернуть документацию до изменений |
| 1 | Снять свежие read-only срезы SPB-SW-409, SPB-SW-410, AL-SPB-MILLION, определить свободные порты и L2-путь | Выполнен | Нет изменений сети |
| 2 | Создать и проверить backup/rollback-пакет; утвердить точные physical ports | Выполнен | Нет изменений сети |
| 3 | Преднастроить только новые VLAN на switch trunks/AP ports; existing VLAN не менять | Выполнен | Удалить только новые VLAN entries |
| 4 | Переместить три кабеля Ideco на SPB-SW-409; проверить management, transit, отсутствие петли | Выполнен | Вернуть три кабеля в исходные порты |
| 5 | Создать на Ideco целевые интерфейсы/DHCP/objects, не подключая клиентов | Выполнен | Отключить/удалить только новые интерфейсы и DHCP |
| 6 | Включить новый corporate SSID только для AD pilot group; проверить users VLAN | Ожидается | Выключить новый SSID либо снять один AP из профиля |
| 7 | Включить guest Wi-Fi, затем зоны устройств по инвентарному плану | Ожидается | По одной зоне / одному устройству |
| 8 | Переносить пользователей волнами, собирать DPI baseline, затем выводить legacy только по отдельному change | Ожидается | Вернуть порт/SSID в legacy VLAN |

**Стоп-условия для каждого write-шага:** нет независимого management доступа,
неясен порт патч-панели, неизвестен путь VLAN до AL-SPB-MILLION, нет backup,
не подтверждён возвратный маршрут или затрагивается существующий VLAN/SSID.

## Результат read-only шага 1

Проверены SSH/LLDP и bridge VLAN tables 06.08.2026.

- `SPB-SW-409`: AP на `ether3–ether8`, `ether20`, `ether21` (7 точек).
- `SPB-SW-410`: AP на `ether2`, `ether7`, `ether9`, `ether15` (4 точки).
- Оба коммутатора подключены к `AL-SPB-MILLION`: SW-409 через router
  `ether2`, SW-410 через router `ether3`; соответствующий L2 uplink на обоих
  CRS — `ether1`.
- Текущий transit VLAN 1461 существует только на ветке router `ether3` ↔
  SW-410 `ether1` ↔ SW-410 `ether11`; адрес router `172.31.146.1/30`,
  return route `10.76.146.0/24 via 172.31.146.2` активны.
- Для переноса transit на SW-409 потребуется добавить VLAN 1461 tagged на
  router `ether2` и SW-409 `ether1`, не удаляя существующую ветку до проверки.
- Подходящие кандидаты свободных портов SW-409 требуют полевой сверки с
  патч-панелью; удалённо нельзя считать no-link доказательством отсутствия
  зарезервированного кабеля.

## Результат шага 2: точка отката

Создан независимый rollback-пакет
`recovery/20260806-ideco-parallel-prechange/` (права доступа к каталогу
ограничены владельцем):

- `AL-SPB-MILLION`, `SPB-SW-409`, `SPB-SW-410`: по одному RouterOS binary
  backup и по одному `export hide-sensitive`;
- Ideco SPB: штатный backup от `2026-08-06 00:00 MSK`, скопированный из
  `/var/backups/`;
- целостность всех семи файлов проверена SHA-256; значения записаны в
  `SHA256SUMS` внутри того же каталога.

Конфигурация оборудования в рамках первоначального backup-шагa не менялась.
Точные порты утверждены: `SPB-SW-409 ether13` — management (legacy VLAN 30),
`ether15` — LAN trunk (только tagged target VLAN), `ether16` — transit
(access VLAN 1461).

## Результат шага 3: L2-подготовка

- На `AL-SPB-MILLION` target VLAN `1400,1440,1450,1470,1480,1490,1500,1510,
  1520` разрешены tagged на router `ether2` и `ether3`; VLAN 1461 теперь
  tagged на обоих uplink, но старая ветка не удалялась.
- На `SPB-SW-409` target VLAN идут tagged через `ether1`, все семь AP-портов
  (`ether3–ether7`, `ether20`, `ether21`) и новый Ideco LAN `ether15`.
- На `SPB-SW-410` target VLAN идут tagged через `ether1` и все четыре
  AP-порта (`ether2`, `ether7`, `ether9`, `ether15`).
- Для сохранения работающего `Aurora-Security-Pilot` VLAN 1460 временно
  протянут через оба uplink и будущий Ideco LAN; его старые порт и SSID не
  менялись.
- `SPB-SW-409 ether13/15/16` получили явные комментарии и `poe-out=off`.
  `ether13` принимает только untagged VLAN 30, `ether15` — только tagged,
  `ether16` — только untagged VLAN 1461.
- После записи проверены таблицы VLAN и SSH всех четырёх устройств. Создан
  post-change пакет `recovery/20260806-ideco-step3-l2-prepared/`.

### Шаг 4: физический перенос (выполняется человеком у стойки)

Переносить **по одному кабелю**, старый порт освобождать до подключения в
новый. Нельзя оставлять одну и ту же связь одновременно на SW-409 и SW-410.

1. Ideco management: `SPB-SW-410 ether13` → `SPB-SW-409 ether13`.
   Подождать линк и подтвердить доступ `192.168.203.82`.
2. Ideco LAN (MAC Ideco `…:DE:00`): `SPB-SW-410 ether6` → `SPB-SW-409 ether15`.
   Проверить доступ тестового SSID и выдачу адреса `10.76.146.x`.
3. Ideco transit (MAC Ideco `…:DE:01`): `SPB-SW-410 ether11` →
   `SPB-SW-409 ether16`. Проверить взаимный ping `172.31.146.2` ↔
   `172.31.146.1` и интернет из test VLAN.

Если один из трёх контрольных тестов не проходит — вернуть только последний
перенесённый кабель на его исходный порт SW-410 и сообщить результат, не
переходя к следующему кабелю.

## Результат шага 4: перенос Ideco

Физический перенос выполнен 06.08.2026:

- `Leth1` (MAC `1C:57:D8:18:DD:FF`) изучен на SW-409 `ether13`, VLAN 30;
- Ideco LAN (MAC `…:DE:00`) — на `ether15`, VLAN 1460;
- Ideco transit (MAC `…:DE:01`) — на `ether16`, VLAN 1461;
- старые SW-410 `ether13`, `ether6`, `ether11` подтверждённо `no-link`;
- линк всех трёх новых портов — 1 Gbit/s full duplex;
- `172.31.146.1` и `.2` пингуются без потерь, SSH на router, двух switches и
  Ideco сохраняется;
- MAC тестового клиента VLAN 1460 виден на SW-410 `ether7`, а MAC Ideco —
  через новый путь. Один MAC не изучается одновременно за разными портами,
  поэтому признаков L2-петли нет.
