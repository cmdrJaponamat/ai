# Машинный OpenVPN: перенос в пул сегментации

**Дата:** 2026-11-03. **Состояние:** применено и проверено.

## Задача и исходное состояние

- Машинный OpenVPN `spb-vpn-srv` (`10.78.4.253`, TCP/6518) сейчас работает с пулом `10.78.91.0/27`; конфиг на диске уже без `ccd-exclusive`, но процесс запущен со старой конфигурацией.
- На AL-OBIT (`10.78.3.254`) есть маршрут `10.78.91.0/27 via 10.78.4.253` и пять узких разрешений к DC/DNS. При этом `LAN+VPN` содержит `10.78.0.0/16`, а более ранние общие разрешения делают эти пять правил недостаточными для изоляции.
- Целевой адресный план отводит VPN-адресам `10.253.0.0/16`. Для машин до входа пользователя резервируется отдельный пул `10.253.91.0/24` с отдельной политикой. В маршрутах, интерфейсах, IP-пулах и address-list AL-OBIT совпадений с `10.253.91.0/24` не найдено.
- На сервере `ip_forward=1`, `FORWARD ACCEPT`; DNS на `10.78.4.253` разрешает `10.0.0.0/8`, поэтому новый пул не требует изменения Unbound.

## Выполненные изменения

1. На `spb-vpn-srv` сохранены исходные `/etc/openvpn/server-device.conf`, `/etc/iptables/rules.v4` и вывод `iptables-save` в `/root/openvpn-device-segmentation-20261103-124815/`.
2. На AL-OBIT создан активный маршрут `10.253.91.0/24 via 10.78.4.253`. Пять разрешений к DC/DNS и `drop` для остального трафика машинного пула помещены после `established,related`, перед общими разрешениями. Старые маршрут и пять правил `10.78.91.0/27` удалены после проверки подключения.
3. На VPN-сервере добавлены сохранённые в `/etc/iptables/rules.v4` ограничения: `INPUT` с `tun-device` только DNS на `10.78.4.253`; `FORWARD` с `tun-device` только AD-порты и ICMP к `10.78.3.50`; затем `DROP`. `iptables-restore --test` прошёл до применения. Существующие правила других VPN-пулов сохранены.
4. `/etc/openvpn/server-device.conf`: пул `10.253.91.0/24`, `max-clients 250`; перезапущен только `openvpn@server-device`. DNAT TCP/6518 не менялся.
5. В проектных документах сегментации `10.253.91.0/24` помечен отдельной зоной `VPN-DEVICES`, исключённой из общих разрешений `VPN-USERS`.
6. Каталог `/etc/openvpn/ccd-device` с двумя устаревшими файлами перенесён в `/root/openvpn-device-segmentation-20261103-124815/ccd-device`. Ни одна действующая конфигурация OpenVPN не ссылалась на этот каталог; другие каталоги CCD не затронуты.

## Проверка

- `openvpn@server-device` и `netfilter-persistent` активны; `tun-device` имеет `10.253.91.1/24`; на AL-OBIT новый маршрут активен, шесть новых правил действуют в нужном порядке, старый маршрут отсутствует.
- После рестарта `AL-SAIKINA` получил `10.253.91.2`, `AL-TEST` получил `10.253.91.3`; оба находятся в списке подключений. Счётчики сервера и AL-OBIT показывают DNS и обращения к DC через новые разрешения.
- Проверка обработки машинных GPO на самих Windows-клиентах в этот эпизод не выполнялась.

## Откат

- Сначала на AL-OBIT восстановить маршрут `10.78.91.0/27 via 10.78.4.253` (комментарий `VPN device pilot pool via spb-vpn-srv`) и пять разрешений к `10.78.3.50` (UDP `53,88,123,389,464`; TCP `53,88,135,389,445,464,636,3268,3269,49152-65535`; ICMP) и `10.78.4.253` (UDP/TCP 53) перед финальным `DROP_ALL`.
- На сервере вернуть `/root/openvpn-device-segmentation-20261103-124815/server-device.conf` в `/etc/openvpn/server-device.conf` и `rules.v4` в `/etc/iptables/rules.v4`; выполнить `sudo iptables-restore /etc/iptables/rules.v4` и `sudo systemctl restart openvpn@server-device`.
- После появления клиентов в старом пуле удалить на AL-OBIT шесть правил с комментарием `VPN device segmented -> ...` и маршрут с комментарием `VPN device segmented pool via spb-vpn-srv`.
- Если снова потребуются прежние CCD, вернуть каталог из `/root/openvpn-device-segmentation-20261103-124815/ccd-device` в `/etc/openvpn/ccd-device` и добавить директивы в нужный конфиг отдельно.
- Не затрагивать остальные экземпляры OpenVPN, DNAT TCP/6518, общие правила и сети.

**Рестарт:** только `openvpn@server-device`; активные клиенты переподключатся. **Релогин/перезагрузка:** не нужны.
