# Реестр внешней поверхности и PHP2Shell

Дата проверки: 2026-10-22 (Europe/Moscow)
Статус: read-only аудит, изменений инфраструктуры не выполнялось.

## Основание

Проверены CVE-2026-109618 и CVE-2026-109619 (PHP2Shell): уязвимости ядра
PHP с возможным удалённым выполнением кода без аутентификации. Для Ubuntu
22.04 исправление PHP 8.1 выпущено пакетом `8.1.2-1ubuntu2.28` (USN-8948-1).

## Источники и границы достоверности

- `AL-OBIT` (`10.78.0.254`) — live read-only срез RouterOS: активные
  `dst-nat`, WAN INPUT и сервисы маршрутизатора на момент проверки.
- `AL-SPB-MILLION` (`192.168.203.1`) — последний успешный controlled
  Oxidized snapshot: `2026-10-21 13:49:20 UTC`.
- nginx (`10.78.3.1`) и Zabbix (`10.78.3.251`) — live read-only проверка
  виртуальных хостов, PHP-FPM и установленных пакетов.
- Это реестр известных и подтверждённых публикаций данных edge-устройств.
  Он не заменяет внешний scan всех выделенных диапазонов и не включает
  неизвестные публикации у сторонних провайдеров.

## Веб-сервисы за публичным nginx

Внешние TCP 80/443 на `85.114.6.214` направлены на nginx `10.78.3.1`. Его
активная конфигурация содержит следующие публичные имена: `api`,
`autodiscover`, `cloud`, `directum`, `helpdesk`, `helpdesk2`, `hd`, `it`,
`kanban`, `ksc`, `mail`, `mesh`, `otpb`, `rmm`, `tc`, `tc0`, `wiki` и
`zabbix` в зоне `aurora-logistics.ru`.

Наличие PHP доказано только для следующих опубликованных путей:

| Публичное имя | Цепочка | PHP и статус CVE-2026-109618/109619 |
| --- | --- | --- |
| `helpdesk.aurora-logistics.ru`, `helpdesk2.aurora-logistics.ru`, `hd.aurora-logistics.ru` | edge `85.114.6.214:443` → nginx `10.78.3.1` → FastCGI Unix socket → `/var/www/helpdesk.aurora-logistics.ru/html` | **Затронуто:** активен `php8.1-fpm 8.1.2-1ubuntu2.27`; для Jammy исправление начинается с `8.1.2-1ubuntu2.28`. |
| `zabbix.aurora-logistics.ru` | edge → nginx `10.78.3.1` → reverse proxy `10.78.3.251` → nginx/PHP-FPM pool `zabbix` | **Затронуто:** `php8.1-fpm 8.1.2-1ubuntu2.27`; исправление начинается с `8.1.2-1ubuntu2.28`. Zabbix frontend: `6.0.40`. |

На самом nginx также есть слушатель TCP/9088 с FastCGI, но для него не найдено
публичного DNAT на AL-OBIT; публичным он в этом срезе не считается.

Для остальных reverse-proxy upstream PHP не обнаружен на edge. Это не является
доказательством отсутствия PHP внутри соответствующих приложений или
вендорских устройств; особенно отдельно должны быть подтверждены `cloud`
(Synology), `directum`, `otpb`, а также upstream `10.78.3.158` для `api`,
`mesh` и `rmm`.

## Приоритет и следующий шаг

1. В первую очередь обновить на `10.78.3.1` и `10.78.3.251` все пакеты
   PHP 8.1 до `8.1.2-1ubuntu2.28` или новее из Jammy security/updates.
2. После обновления обязательно перезапустить `php8.1-fpm`; затем проверить
   версии пакетов и состояние пулов `www`/`zabbix`.
3. Отдельно проверить вендорские обновления Synology DSM/Drive и всех
   upstream, пока не подтверждён стек каждого сервиса.
4. Так как PHP-точки были публичны до патча, после обновления провести
   проверку журналов и плановую ротацию секретов приложений согласно
   incident-процедуре.

## Откат

Аудит не менял конфигурацию и не требует отката. При будущем обновлении PHP
откатом будет возврат к прежним `.deb` только как аварийная мера; он вернёт
критическую уязвимость и не должен быть штатным решением.

## Reboot/restart

Для текущего аудита: нет. Для исправления: потребуется restart `php8.1-fpm`
на каждом из двух хостов; reboot не ожидается.
