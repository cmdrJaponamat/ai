# L2-транспорт целевой сегментации до PVE

Дата: 2026-09-07. Статус: L2-подготовка завершена; L3/ACL и миграция VM не
выполнялись.

## Цель и границы

Подготовить на AL-OBIT, обоих H3C и `vmbr0` PVE1-PVE3 целевые VLAN ЦОДа из
согласованной матрицы сегментации, сохранив текущую production-сеть VLAN 1
untagged и не затрагивая отдельные iSCSI/Corosync-фабрики.

Разрешённый на серверных uplink набор:

`804-807,1000,1020,1030,1070,1100,1200-1207,1210,1220-1221,1230,1240`.

- `804-807` сохранены как существующие legacy/test VLAN.
- `1040/1050` не добавлены на `bond0`: iSCSI использует отдельные NIC и
  нетегированные сети `10.78.4.0/24` и `10.78.5.0/24`.
- `1060/1061` не добавлены на `bond0`: Corosync использует отдельные
  физические интерфейсы/VLAN.
- Новые SVI, IP, DHCP и firewall allow не создавались. Текущие подсети на
  общем untagged bridge AL-OBIT не мигрировали.

## Изменения H3C

На upper `10.78.2.11` и lower `10.78.2.12`:

- созданы все VLAN из указанного списка (VLAN 1070 существовал после
  предыдущего этапа);
- `XGE1/0/48` сохраняет VLAN 1 и несёт весь список tagged между H3C;
- `XGE1/0/54:1` сохраняет VLAN 1 untagged/PVID 1 и несёт список tagged до
  active-backup `LAG-SW` AL-OBIT;
- серверные `XGE1/0/2`, `3`, `4` переведены в hybrid: VLAN 1 untagged,
  целевой список tagged;
- конфигурации обоих H3C сохранены `save force`.

Порты новой Synology `54:2-4` остаются отдельными access VLAN 1070 и в этот
серверный trunk не входят.

## Изменения AL-OBIT

- Существующие записи VLAN `804-807`, `1000`, `1070` сохранены.
- Для `1020,1030,1100,1200-1207,1210,1220,1221,1230,1240` добавлены только
  bridge VLAN entries с `tagged=bridge,LAG-SW` и комментариями
  `DC segmentation L2 staged VLAN...`.
- Перед изменением созданы RouterOS backup/export
  `pre-dc-segmentation-l2-20260907-123516`.

## Изменения PVE

На `vmbr0` PVE1-PVE3 включены:

```text
bridge-vlan-aware yes
bridge-vids 804-807 1000 1020 1030 1070 1100 1200-1207 1210 1220-1221 1230 1240
```

Изменения сделаны через Proxmox API и применены штатным network reload.
Резервные копии исходных файлов:

- PVE1: `/root/interfaces.pre-dc-segmentation-20260907-123839`;
- PVE2: `/root/interfaces.pre-dc-segmentation-20260907-123938`;
- PVE3: `/root/interfaces.pre-dc-segmentation-20260907-123647`.

## Проверка

- Все три reload-задачи Proxmox завершились `OK`; runtime `vmbr0` показывает
  `vlan_filtering 1`, а `bond0` — весь ограниченный список VLAN.
- VM107 временно переключалась с VLAN 804 на VLAN 1070. Из гостевой ОС с
  временным `10.78.7.107/24` получено 5/5 ответов от шлюза `10.78.7.254`.
  После теста временный IP удалён, конфигурация VM возвращена точно к
  `tag=804`; QEMU Guest Agent отвечает.
- Отдельный host-тест с PVE3 через `bond0.1070` дал 5/5 до `10.78.7.254`;
  временный интерфейс удалён.
- После изменений все H3C, AL-OBIT, PVE и старая Synology отвечают; ICMP
  baseline 0% loss. На каждом PVE quorum `Yes`, NFS `synology` active,
  failed systemd units отсутствуют.

## Откат

1. На PVE по одному узлу восстановить его named backup
   `/etc/network/interfaces`, применить Proxmox network reload и проверить
   management/quorum/storage до следующего узла. Альтернатива: через API
   удалить `bridge_vlan_aware` и `bridge_vids` с `vmbr0`.
2. На AL-OBIT удалить только bridge VLAN entries с комментариями
   `DC segmentation L2 staged VLAN...`; не удалять существующие 804-807,
   1000 и 1070. При аварийном откате с локальной консоли использовать
   `pre-dc-segmentation-l2-20260907-123516`.
3. На обоих H3C удалить целевые tagged membership с `XGE1/0/2-4`, `48` и
   `54:1`; вернуть серверные порты и 54:1 в access VLAN 1, а 48 — в прежний
   access VLAN 1. Удалять сами VLAN только после подтверждения отсутствия
   membership. Откатывать по одному H3C с проверкой active-backup.

Relogin/restart/reboot: не требуется.

## Следующие шаги

- После включения новой Synology подтвердить фактический `54:2`, убрать
  временную access-конфигурацию с неиспользуемых `54:3/54:4` и назначить NAS
  `10.78.7.10/24`.
- Для каждой VM отдельно согласовать целевую зону, зависимости, шлюз и ACL;
  только затем менять её VLAN/IP. Наличие L2 VLAN не означает готовность L3.
