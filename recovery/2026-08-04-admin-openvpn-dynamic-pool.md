# Административный OpenVPN: исключение статического адреса из динамики

## Проблема

Клиент `admin-al` имеет статический адрес `10.78.90.34`, но встроенный
динамический пул `server 10.78.90.32/27` тоже мог назначить этот адрес другому
пользователю. В журнале сервера подтверждена выдача `.34` `b.zubov`, что
переназначало маршрут и оставляло один из клиентов с формально поднятым, но
нерабочим туннелем.

## Изменение

На `spb-vpn-srv` в `/etc/openvpn/server-admin.conf` после директивы `server`
добавлено:

```conf
ifconfig-pool 10.78.90.35 10.78.90.62 255.255.255.224
```

Перед изменением сохранена копия
`/etc/openvpn/server-admin.conf.backup-20260804-1528`.

## Проверка

- `openvpn --config /etc/openvpn/server-admin.conf --test-crypto` успешно
  принял обновлённую конфигурацию.
- Выполнен перезапуск только `openvpn@server-admin`; локальный TCP-клиент
  после этого удерживает устаревшую сессию и требует наблюдения/ручного
  переподключения перед финальной проверкой статуса и выдачи адреса.

## Откат

На `spb-vpn-srv`:

```bash
sudo cp -a /etc/openvpn/server-admin.conf.backup-20260804-1528 /etc/openvpn/server-admin.conf
sudo systemctl restart openvpn@server-admin
```

## Следующий шаг

После переподключения клиента проверить `/var/log/openvpn-status/openvpn-admin-status.log`:
`admin-al` должен иметь `.34`, а новые динамические клиенты — адреса от `.35`.
