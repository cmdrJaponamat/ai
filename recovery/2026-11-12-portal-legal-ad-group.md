# Подключение группы AD для юридической очереди PortalAL

Дата: 2026-11-12. Пользователь создал группу `App-Portal-Legal-Operators` для исполнителей юридической очереди.

## До изменения

- LDAP-запрос из контейнера портала нашёл единственную группу `CN=App-Portal-Legal-Operators,OU=Applications,OU=CompanyGroups,DC=aurora-logistics,DC=local`; тип — глобальная security group, участников пока нет.
- В PortalAL код роли `legal` уже есть, но `PORTAL_LEGAL_GROUP_DN` в production `.env` не установлен. Доступ к рабочей очереди имеют администраторы портала.
- Образ портала до изменения: `portal-al:c6e0a42f39b29cf97944679b5745a3a5e6bf5708`, healthy. Конфигурация в `/opt/portal-al/.env` mode 0600.

## План и откат

1. Сохранить копию production `.env` с прежними правами, добавить точный DN группы. Обновить примеры конфигурации в репозитории, запустить штатный CD для применения переменной.
2. Проверить health, роль для DN и отсутствие роли для чужой группы. При появлении участников создать отдельные профили исполнителей в юридическом HESK с нужными правами; пока группа пустая, не выдавать профили наугад.
3. Откат: восстановить `.env.before-legal-role-20261112` на `10.78.3.149` и пересоздать контейнер с текущим образом через `PORTAL_IMAGE=<current> docker compose up -d --no-build portal`; либо убрать переменную и повторить CD. Отдельный HESK и ИТ очередь не меняются.

## Фактические действия и новая находка

- В production `.env` добавлен DN группы; прежняя версия сохранена как `/opt/portal-al/.env.before-legal-role-20261112` mode 0600. Примеры `.env` обновлены коммитом PortalAL `5dbfd4f`. CI/CD успешны, контейнер `portal-al:5dbfd4f6bbbaeec0dd4e4cf76591ea035423780e` healthy, роль `legal` вычисляется для прямого члена группы.
- Пользователь добавил в `App-Portal-Legal-Operators` вложенную группу `Role-UKPV`, а не отдельных пользователей. AD matching rule `1.2.840.113556.1.4.1941` нашёл четырёх активных сотрудников: `e.gubenko`, `p.hrulev`, `e.kudym`, `s.ziborov`. Все входят косвенно; прямой `memberOf` не содержит группу приложения. Обычный вход в портал пока не даст им роль `legal`.
- Проверен адресный LDAP-запрос на вложенное членство: для `e.gubenko` результат есть, для `a.kuznetsov` результата нет. В `server/auth.mjs` готовится проверка этого условия при входе в портал. Ошибка дополнительного поиска не даёт юридическую роль и не ломает общий вход.
- Перед изменением HESK запущен `hesk-legal-db-backup.service` на `10.78.3.2`; результат `success`, архив `helpdesk_legal-20261112-103046.sql.gz`. Исходный `/etc/hesk-legal/credentials.json` сохранён как `credentials.json.before-operators-20261112` mode 0600.
- В юридической БД созданы профили `e.gubenko` (id 3), `p.hrulev` (id 4), `e.kudym` (id 5), `s.ziborov` (id 6). У каждого `isadmin=0`, категория `1` (`General`), права `can_view_tickets,can_reply_tickets,can_resolve,can_assign_self,can_view_unassigned,can_view_ass_others`; все флаги почтовых уведомлений 0. Случайные локальные пароли сохранены только в root-only `/etc/hesk-legal/credentials.json` и не передавались в чат или логи.
- Подписанный bridge `/operators/<login>` подтвердил все четыре профиля, права и отсутствие `isAdmin`; `/tickets` показал для каждого юридические заявки. Код проверки вложенной группы отправлен в PortalAL коммитом `fa4033f`.

CI и CD коммита `fa4033f` завершились успешно. Контейнер `portal-al:fa4033f6c35127c90c2ae7923c10e05c40e3166a` healthy, `/api/health` вернул HTTP 200. Работающий `lookupLdapUser` дал роль `legal` четырём участникам `Role-UKPV`; `a.kuznetsov` её не получил и сохранил `admin/it`. Пользователям с уже открытой сессией нужен повторный вход, поскольку роли сохранены в сессии. Авторизованный браузерный вход самих юристов пока не проверен.

Откат профилей: остановить обращения через портал, восстановить юридическую БД из архива `helpdesk_legal-20261112-103046.sql.gz` с учётом заявок, созданных после архива, либо вручную удалить только профили id 3–6 после проверки, что на них нет назначений/ответов. Восстановить `credentials.json.before-operators-20261112` при полном откате. Откат вложенного членства: `git revert fa4033f` и штатный CD; чтобы отключить всю роль, восстановить production `.env.before-legal-role-20261112` и пересоздать контейнер. Перезагрузка серверов не нужна.
