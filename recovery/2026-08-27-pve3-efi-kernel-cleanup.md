# spb-pve3: восстановление EFI и kernel-пакетов

Дата: 2026-08-27, MSK  
Статус: выполнено, перезагрузка отложена до сервисного окна.

## Проблема

На `spb-pve3` ESP `/boot/efi` размером 1022 МБ был заполнен на 93% (944 МБ),
из-за чего 15 kernel-пакетов Proxmox остались в состояниях `half-configured` /
`unpacked`. Нода продолжала работать на `6.14.11-3-pve`.

## Что сделано

1. Создан архив исходного содержимого ESP:
   `/root/boot-efi-precleanup-20260827-180228.tar` на `spb-pve3`.
2. До восстановления удалены с ESP только устаревшие копии; сохранены текущее
   ядро и загрузочный резерв.
3. Выполнен `dpkg --configure -a` после освобождения места.
4. Штатно удалены только устаревшие `proxmox-kernel` пакеты; пользовательские
   пакеты из общего списка `apt autoremove` не удалялись.

## Итоговая проверка

- `/boot/efi`: 433 МБ из 1022 МБ, свободно 590 МБ (43% занято).
- `dpkg --audit` не выводит проблемных пакетов; `apt-get check` завершён без
  ошибок.
- На ESP присутствуют загрузочные записи: `6.14.11-3-pve` (текущее),
  `6.14.11-6-pve`, `6.17.13-7-pve`, `7.0.0-3-pve`, `7.0.2-2-pve` (default).
- `pve-cluster`, `corosync`, `pvedaemon`, `pveproxy` — active.
- Кластер `SPB-OBIT-DC`: 3 ноды, `Quorate: Yes`.

## Откат

До перезагрузки текущим остаётся `6.14.11-3-pve`. Если потребуется восстановить
удалённую EFI-копию, использовать архив из `/root` только из BMC/локальной
консоли и только после оценки пространства на ESP. Пакеты намеренно не
восстанавливать массово: они уже штатно удалены APT.

## Следующий шаг

В согласованное сервисное окно перезагрузить только `spb-pve3`, проверить
загрузку в `7.0.2-2-pve`, затем `pvecm status`, `corosync-cfgtool -s`,
management, storage и ВМ. До подтверждения загрузки не удалять сохранённые
версии ядра.
