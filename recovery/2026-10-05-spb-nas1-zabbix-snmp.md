# SPB-NAS1: восстановление SNMP-мониторинга Zabbix

**Дата:** 2026-10-05  
**Zabbix:** `10.78.3.251`  
**NAS:** `SPB-NAS1`, management `10.78.0.250`

## Исходное состояние

В Zabbix уже существовал хост `SPB-NAS1` (ID `10735`) в группе `SAN` с
шаблоном `Synology DiskStation`. Его единственный интерфейс SNMPv2 (ID `126`)
был задан как `10.78.0.10:161` и находился в состоянии unavailable с ошибкой
таймаута.

На NAS служба SNMPv1/v2 включена с согласованным сообществом. Прямой запрос с
Zabbix-сервера к `10.78.0.250` успешно вернул `sysName=SPB-NAS1`.

## Изменение

- В Zabbix изменён только IP интерфейса ID `126`: `10.78.0.10` →
  `10.78.0.250`.
- Порт остался `161`, тип — SNMPv2.
- Шаблон `Synology DiskStation`, группа `SAN`, настройки SNMP NAS и прочие
  хосты не менялись.
- На Zabbix выполнено `zabbix_server -R config_cache_reload`.

## Проверка

- Прямой SNMPv2 запрос с `10.78.3.251` к `10.78.0.250:161` успешен.
- После следующего опроса интерфейс имеет `available=1`, поле ошибки пустое.

## Откат

Если потребуется вернуть заведомо устаревший endpoint, в Zabbix изменить
интерфейс хоста ID `10735`, интерфейс ID `126`, обратно на `10.78.0.10`.
Данные NAS и шаблон при этом не затрагиваются. Предпочтительный вариант —
оставить актуальный management IP `10.78.0.250`.

## Следующий этап

Добавить отдельную проверку доступности пользовательского файлового endpoint
`10.78.7.10` (ICMP и, при необходимости, TCP/445). Её не следует смешивать с
SNMP management-полки: это независимый сервисный путь.
