## 6. FORWARD: сегментация пилотного VLAN

- [x] Широкое правило `10.76.146.0/24 → any` заменено allow-list моделью.
- [x] Разрешены только: не-corporate Internet, 13 доступных `shared_srvs`,
  `spb-dc1-al`, корпоративный resolver и `10.77.0.0/24` по Ideco S2S.
- [x] Добавлен финальный FORWARD drop для остального трафика VLAN 1460.
- [ ] С авторизованного клиента выполнить:

```powershell
Test-NetConnection 1.1.1.1 -Port 443
Test-NetConnection 10.78.3.50 -Port 88
Test-NetConnection 10.78.3.1 -Port 443
Test-NetConnection 10.77.0.253 -Port 8443
Test-NetConnection 192.168.203.1 -Port 22
```

Ожидание: Internet и `10.78.3.50:88` проходят, последняя проверка не
проходит. Для `10.78.3.1:443` и `10.77.0.253:8443` успешный TCP зависит от
наличия конкретного сервиса на цели; их назначение в этом тесте — подтвердить
счётчиками прохождение через corporate/S2S allow-rule, а не доступность
произвольного порта. После теста должны увеличиться соответственно counters
FORWARD Internet, corporate/S2S и final deny.

- [ ] Проверить, что `10.10.20.50` недоступен предсказуемо, и не добавлять его
  в allow-list до исправления обратного пути.
- [ ] Проверить, что произвольные private-адреса, например
  `10.78.200.1:443`, не проходят и учитываются final deny.

## 10. Критерии готовности к переносу модели на Ideco Москва

Все пункты ниже — блокирующие:

- [ ] Реальный клиент прошёл DHCP, Интернет, DNS, Kerberos и доступ к каждому
  объявленному corporate-сервису.
- [ ] Недоменные устройства прошли или явно исключены из первой версии
  политики с документированным временным режимом.
- [ ] FORWARD allow-list и final deny подтверждены счётчиками и отрицательными
  тестами.
- [ ] INPUT allow-list подтверждён разрешённым и запрещённым источником;
  подтверждён web-auth и плановый IKE rekey.
- [ ] Согласован и проверен обратный маршрут Москва ↔ СПБ для пользовательских
  сетей, а не только для самих Ideco.
- [ ] Определены правила управления московским узлом, его реальные интерфейсы,
  адреса администраторов и локальные сервисы. Нельзя переносить внутренние ID
  `interface.id.*`, `subnet.id.*`, `port.id.*` со СПБ: на Москве они должны
  быть сопоставлены заново по назначению.
- [ ] Создан актуальный backup обоих Ideco, протестирован документированный
  откат и назначено окно переноса.

## 11. Эксплуатация после пилота

- [ ] Ежемесячно сверять allow-lists с реестром `shared_srvs` и владельцами
  сервисов; не расширять их широкими `/16` без отдельного решения.
- [ ] Отслеживать истечение/смену публичного адреса московского IPsec-пира.
- [ ] После появления AD-сайта в ОП вернуться к EAP-TLS/RADIUS как штатной
  Wi-Fi-аутентификации; текущий web-auth считать пилотной переходной схемой.
- [ ] Оформить конечную site-модель Ideco для users, AP management, guest,
  CCTV, NVR, ACS, voice, print devices и print services; текущая конфигурация
  покрывает только users-пилот.
